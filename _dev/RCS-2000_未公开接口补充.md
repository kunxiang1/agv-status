## A1 登录*

| | |
|---|---|
| 接口名 | login.action |
| 功能说明 | 获取 CMS 会话 Cookie，之后才能调用 A2~A5 |
| 接口协议 | HTTP Form |
| 提供方 | RCS-2000（Web CMS） |
| 调用方 | 上层系统 |
| 调用路径 | `POST http://IP:8181/rcms/web/login/login.action` |

### 请求参数

| 参数名 | 数据类型 | 是否必填 | 备注 |
|---|---|---|---|
| ecsUserName | String | 是 | 用户名（现场：admin） |
| ecsPassword | String | 是 | **不是明文**，= 密码原文的 SHA-256 十六进制小写（64 位） |
| pwdSafeLevelLogin | String | 否 | 密码安全等级，实测传 `"0"` 可用 |

### 应答

成功：`{"success":true}`，响应头下发 `Set-Cookie: JSESSIONID=...; HIK_COOKIE=...`。

失败：`{"code":"1","msg":"用户名或密码错误,您还有N次机会","success":false}` —— **连续错会锁定账号**，程序里凭据只配一次，勿循环重试。

### 示例

```
POST /rcms/web/login/login.action
ecsUserName=admin&ecsPassword=<sha256(密码)>&pwdSafeLevelLogin=0
```

## A2 查询地图内容（拓扑地图 XML）*

| | |
|---|---|
| 接口名 | findByElcMapCode.action |
| 功能说明 | 取指定地图的**完整拓扑地图 XML 源文件**，与 CMS 界面"地图编辑→地图导出"下载到的 `地图-时间戳QR.xml` 为同一数据，且**始终最新**（导出文件可能带着过期的 `IsUpdateMap` 标记差异，拓扑内容一致） |
| 接口协议 | HTTP Form |
| 提供方 | RCS-2000 |
| 调用方 | 上层系统（需先 A1 登录） |
| 调用路径 | `POST http://IP:8181/rcms/web/elcMap/findByElcMapCode.action` |

### 请求参数

| 参数名 | 数据类型 | 是否必填 | 备注 |
|---|---|---|---|
| elcMapCode | String(32) | 是 | 地图编号（如 BB）；缺失时返回 `{"success":false}` |

### 应答

| 字段 | 备注 |
|---|---|
| success | 布尔 |
| elcMapCode / elcMapName | 地图编号 / 名称（如 BB / 二厂3楼） |
| orgCode | 组织编号（现场 1001） |
| **elcMapContent** | **Base64( gzip( UTF-8 地图XML ) )**，解码即得 `<MapCfg>` 文档（PointInfo 节点：id/xpos/ypos 单位米/value 类型；NeighbInfo 内 id+distance 为邻接边） |
| elcMapRowCount / elcMapColCount / width / height | 500 / 500 / 1000 / 1000（栅格尺寸） |
| rowToDown / colToLeft / xOffset / yOffset | 原点偏移，常为 0 |
| mapVersionId | 地图版本号（字符串），改图会变，**可当"是否有更新"的水印**（实测 BB=624） |
| refreshMap / podDirConf | 刷新标志 / 货架方向配置，值 "1" |

### 示例

```python
d = post("/rcms/web/elcMap/findByElcMapCode.action", {"elcMapCode": "BB"})
xml = gzip.decompress(base64.b64decode(d["elcMapContent"])).decode("utf-8")
```

## A5 地图数据导出（Excel）

| | |
|---|---|
| 接口名 | export.action（mapData 模块） |
| 功能说明 | 导出地图地码数据为 .xls（**不是**拓扑 XML，拓扑用 A2） |
| 调用路径 | `POST http://IP:8181/rcms/web/mapData/export.action` |

请求参数（表单，均可缺省，实测只传 mapCode 也出文件）：`mapCode`（是）、`mapDataCode`、`dataTyp`、`dataName`、`podCode`、`areaCode`、`stgSecCode`、`exportCookieId`。

应答与机制（官方前端 common.js `jExport`/`judgeExport` 反推 + 实测）：
1. 成功时响应头 `Content-Type: application/octet-stream`、`Content-Disposition: attachment;fileName=地图数据-yyyyMMddHHmmss.xls`，主体即文件字节；
2. 同时服务端 `Set-Cookie: <exportCookieId>=true; Max-Age=3`——前端轮询该 cookie 判断"导出完成/失败"，失败时错误信息在 `<exportCookieId>_Msg` cookie。**程序化调用直接读响应体即可，无需轮询**；
3. `exportCookieId` 官方前端用"毫秒时间戳"，用途是同浏览器多导出互不串扰，唯一即可。

## A6 queryAgvStatus 未公开字段（对官方 3.1.9 的勘误）

官方文档应答字段表之外，8083 实测**还会返回**：

| 字段 | 类型 | 备注 |
|---|---|---|
| online | Boolean | 车是否在线（离线判断用 `!online` 比超时更直接） |
| timestamp | Long | 服务端采样时刻（毫秒），做数据新鲜度/动画时钟用 |

另实测 **mapShortName 拼错（含中文简称、不存在名）不报错**，一律 `{"code":"0","data":[]}` —— 别依赖返回码发现配错图号，应校验 data 非空或对照 A3 的 code 列表。

另两处实测与文档不一致：
- **path 语义**：官方注明"执行路径"。实测是**本次任务已走过的路线折线**（path[0]=任务起点、尾点≈车当前位置，任务完成后清空），不是未来规划；
- **status 取值**：文档附件 6.1 只列 30 余条，设备固件实际返回更多（如 **246=待机模式**、247/248=低功耗/休眠）；完整 168 条以《移动机器人告警信息表 V5.3》工作表"v.1机器人状态值"为准（本项目已导出为根目录 status.js）。
- 调用频次约定（<100 车 5s / 100~200 车 10s / 200~300 车 15s）为文档要求，8083 无 IP 白名单、**无 CORS 头**（OPTIONS 预检返回 500），浏览器跨域直连不可行，需本地代理转发。

## A7 错误码与通用应答约定（CMS）

| 场景 | 实测表现 |
|---|---|
| 成功 | `{"success":true}` 或 `{"code":0,...}` |
| 未登录/会话过期 | **不是 302**：返回 JSON，`{"message":"http://IP:8181/rcms/web/login.action",...}`（前端 iframe 用 system-tip.jsp 提示）。程序侧以"响应体含 login.action 跳转地址"判定需重新登录 |
| 登出 | `GET /rcms/web/logout.action` → `{"success":true}`，会话立即失效 |
| 参数缺失 | 多为 `{"success":false}`（无 msg） |
| 8182 hikRpcService（syncMapDatas 等官方接口） | 有 **IP 白名单**：非白名单返回 `{"code":"5","message":"IP不在允许名单中,IP:xxx","validFlag":false}`；8083 与 8181 均无 |
| 不存在的 action | Jetty 404 HTML（`/rcms-dps/rest/*` 下如 GetMapListInfo 即 404，**不存在此接口**） |

## A8 getRabbitMqParam（RabbitMQ 连接参数下发）

| | |
|---|---|
| 接口名 | getRabbitMqParam |
| 功能说明 | 下发 WMS/上层系统接 RCS 消息总线（RabbitMQ）的账号与地址 |
| 接口协议 | HTTP **GET**（POST 一律 405） |
| 提供方 | RCS-2000（Web CMS 8181） |
| 调用路径 | `GET http://IP:8181/rcms/services/rest/clientService/getRabbitMqParam` |
| 鉴权 | 需先登录（A1 Cookie 会话） |

实测应答（现场，XML 不是 JSON）：

```xml
<?xml version="1.0" encoding="utf-8" standalone="yes"?>
<result>
    <rabbitmpUser>root</rabbitmpUser>          <!-- 注意官方拼写 rabbitmpUser（少 q） -->
    <rabbitmqExchange>exchangeMsg</rabbitmqExchange>
    <rabbitmqIp>mq-ip</rabbitmqIp>
    <rabbitmqPassword>[REDACTED-MQ-PWD]</rabbitmqPassword>
    <rabbitmqPort>5672</rabbitmqPort>
</result>
```

`.39:15672` 管理台实测：`exchangeMsg`、`exchangeMsg4App` 均 fanout 型；当前 6 条 GUID 命名独占队列各挂 1 个消费者（≈0.4 条/秒）——每个上层客户端一条队列。官方 MonitorClient 二进制内有 `rabbitmqmgr.cpp`（日志 119 处 `rabbitmq connect succeed`），**它就是这条通道的消费者之一**——货架/任务的全量信息不止 REST 一条路，MQ 上 `exchangeMsg` 是 RCS 广播总入口（本项目未接，ZMTP 6990 已够用；要接时账号密码现取 A8 接口、连 rabbitmqIp:5672，AMQP 需第三方库，违背纯标准库原则，谨慎）。

## A10 getShareMapInfoByMapCode（地图背景区域，官方底图数据源）

| | |
|---|---|
| 接口名 | getShareMapInfoByMapCode |
| 功能说明 | 按图返回**区域多边形+文字标注**——官方客户端"字符后/沉金前""待曝光区"那层灰白背景+区域名即此数据本地渲染成 `MapBK/Background_*.png` 缓存（exe 字符串+日志 "saving map background..." 实锤） |
| 接口协议 | HTTP POST，`Content-Type: application/json` |
| 调用路径 | `POST http://IP:8181/rcms/services/rest/clientService/getShareMapInfoByMapCode` |
| 鉴权 | 登录 Cookie 即可，**无 IP 白名单** |

请求 `{"mapCode":"BB"}` → 应答 `{"mapCode":"BB","shareInfos":[{"type":"1","content":"<MapRetCfg XML>"}]}`（type=1 区域背景；现场仅此一类）。

content XML（**单位毫米**，`\r\n` 分隔）：
- `<MapRet>` × N：多边形 = 若干 `<Point xpos= ypos=/>` + `<Area color_a="255" color_r="218" color_g="220" color_b="223"/>` 填充色（现场全部区域同一灰 RGB 218,220,223）
- `<RetName start_x start_y end_x end_y size font font_color_* >文字</RetName>` × M：区域名标注。**竖排名**（"待曝光区"等）在 XML 里逐字 `\n` 分隔且框高≫宽；`&` 以 `&amp;` 实体存放（如"开料&内层前处理"——不反转义会漏字）。`size` 是恒定屏幕像素字号（官方同样不随地图缩放）。

实测数量：BB 4 多边形/4 标注、EE 10/6、CC 6/15、DD 4/3。本项目已接入（rcs_rets.py，「同步地图」时拉，产物 maps/rets.json）。
**相关但不可用**：`getSlamMapContentByCode` 各种入参均回空 body（现场未配 SLAM 栅格底图）；443/nginx 上无背景资源。

| | |
|---|---|

| 鉴权 | 登录 Cookie 即可，无 IP 白名单 |

请求 `start=1&limit=5&mapCode=CC` → 应答：

```json
{"total":661,"code":0,"data":[{
  "dataName":"1005443CC0046398",   // 地标码（=地图数据编号 mapDataCode，1+7位x毫米+图码+7位y毫米）
  "dataTyp":"16","dataTypName":"高速区","cooX":-5443.0,"cooY":46398.0,
  "areaCode":"","stgSecCode":"",    // ← 区域/库区归属；非储位类点常为空
  "mapCode":"CC","mapName":"二厂2楼","dir":"","status":1,"indLock":0,
  "chargeDeviceType":"","deviceTypeCode":"","orgCode":"1001","orgName":"1001"}, ...]}
```

配套：`/rcms/web/stgSec/getStgSecByAreaCode.action?（form: areaCode=zhhsh）` 按区域列库区段（行含 `stgSecText` 名/`maskNum`）；`/rcms/web/mapData/imp.action`、`fieldExtExport.action`、`virPodExport.action` 等是同模块的导入导出兄弟接口。
**本项目用途**：地标码→区域名成员表，落 `rets.json` 的 `slotAreas`（空储位/工作区悬停显示区域的数据源）。
**行类型（`dataTyp`）实测**：`0/1`=储位、**`10`=工作区**、`16`=高速区/路径点、`15`=自动门、`11`=充电区、`19`=暂驻区、`22`=电梯交接区、`52`=电梯等待点。

**⚠️ 别把 `dataTyp` 当地图节点类型**：`maps/*.json` 的 `node[3]` 是另一套编码，同一个地标可能地图=0、A12=10
（用户 2026-09-14 报的 `007432BB050163`：A12 `dataTyp=10`/`areaCode=字符机台区`，而 BB 地图节点类型=`0`）。
**`dataName` 有两代长度**：新版 14 字符（6位x毫米+图码+6位y毫米，如 `045132BB065293`）；
官方偶发 16 字符老式码（`1+7位x毫米+图码+7位y毫米`，如 DD 的 `0053579DD0034627`）——前端 `cellCode()` 只产 14 位，
16 位老式码匹配不上（无害，仅个别遗留点）。

## A13 getStgSec4Ocx（区域名 → 库区序号 maskNum，区域的可靠标识）

| | |
|---|---|
| 接口名 | stgSec/getStgSec4Ocx.action |
| 功能说明 | 客户端的「**地图编辑 → 库区编辑 → 库区类型名称**」下拉数据源：每行 = 一个区域/库区，带区域中文名与**库区序号 `maskNum`**。用户口径：**序号才是区域的可靠来源（不重复）** |
| 接口协议 | HTTP **form POST** |
| 调用路径 | `POST http://IP:8181/rcms/web/stgSec/getStgSec4Ocx.action`（body `mapCode=BB`） |
| 鉴权 | 登录 Cookie 即可，无 IP 白名单（**8181**，与 8182 hikRpcService 无关） |

应答**是数组**（不是 `{rows:...}`）：

```json
[{"areaCat":"1","areaTypCode":"ZFJT","areaTypText":"字符机台区","mapCode":"BB",
  "maskNum":109,"priority":1,"stgSecCode":"6","stgSecText":"字符机台"}, ...]
```

- **`maskNum`（库区序号）全局唯一、跨图也不重复**：实测四图合计 128 个区域名 ↔ 128 个序号一一对应，
  无同名歧义 → 用户指的「序号值 109 / 名称 字符机台区」即此行（`areaTypText=字符机台区`, `maskNum=109`）。
- 与 A12 的关联键 = **`areaTypText` ↔ A12 行的 `areaCode`**（精确字符串匹配）：
  实测四图 A12 去重区域名 10/7/12/84 个，在 `areaTypText` **100% 命中**。
- 行里另带 `areaTypCode`（多数图里与 `areaTypText` 同值的短码，如 `z0`/`p4`；BB 为 `ZFJT` 这类字母码）
  与 `stgSecCode`/`stgSecText`（库区码/名，与 A12 行的 `stgSecCode` 口径不同，**别混用**）。
- 本项目产物：`rets.json` 的 `areaSeq`（`区域名 → maskNum`）。**序号只作内部判据/对账，前端界面不显示**
  （用户明确要求）；前端只要区域中文名（A12 已给），序号用于排障时核对。

### 模块/页面 action 的通用发现法（本轮全部新接口都由此而来）

1. `POST /rcms/web/getMenuListForSeleModule.action` → 模块树（cms_1010=地图规划…）；
2. `POST /rcms/web/getSubMenuList.action`（form `parentMenuCode=cms_1010`）→ 子菜单带 `url`，如「地图数据」=`/web/mapData/cms_index.action`；
3. GET 该页 → 抽 `<script src=…>` 里的模块 JS（`/rcms/web/cms/system/elcmap/js/cms_mapdata.js`）；
4. JS 里正则提 `['"]xxx.action['"]` 即全部真实 action，连分页参数名都写在 `table.render({request:{...}})` 里——**不用猜**。
