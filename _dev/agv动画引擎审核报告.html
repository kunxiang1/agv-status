AGV 实时监控 · 车辆动画引擎审核与修复

对象：agv-web（RCS-2000 Web 监控） · 范围：index.html 动画核心 / server.py / 测试 · 验证：12 组单测 + 真实产线数据端到端 · 备份：*.bak-0910
本次审核还原了整套动画链路的设计意图：上报坐标只做证据，动画永远沿路网折线推进，结构上不允许往回走。 审查发现 3 处会直接产生「漂移 / 回头路」观感的结构性缺陷（贴路反折、轨迹尾拾取、斜穿缓动）和 10 项健壮性缺陷， 已全部修复并重构为「帧可信度分层 → 贴路构图 → 弧长推进」的导航级引擎。 最终用 厂内真实产线数据（BB 图 2 台真车、真实任务运行中）做了端到端验证：动画终态距真实上报位置 0.02–0.33m，全程贴路、无瞬移、单调追帧。

01设计意图还原

系统链路：RCS-2000（rcs-ip:8083）→ 本地代理 server.py（静态页 + 状态转发）→ 前端每 5s 轮询 queryAgvStatus，在 Canvas 拓扑图上渲染车辆。动画的关键前提来自现场实测（_dev/RCS-2000_未公开接口补充.md A6）：

  • path 字段不是规划路线，而是本次任务已走过的历史轨迹（首点=任务起点、尾点≈当前位置、任务完成即清空）；
  • 真实坐标 posX/posY 来自二维码栅格定位，精度高但 5s 才一帧；speed / robotDir 为采样时刻瞬时值；
  • 现场网络会丢包、会重复推帧，AGV 会倒车（车头不动、位置后移），厂区路网为纯直角边（四张图 2179 条边实测 0 斜边）。

原引擎的核心思路是对的：把车约束为「折线上的弧长 s」，s 只增不减，每周期从车头位置重锚折线。这个骨架全部保留，问题出在边界场景的几何与数据可信度处理上。

02导航软件是怎么做的（调研结论）

车标平滑是导航 App 的成熟工程问题，公开资料给出的标准组合拳与本项目高度同构：

导航软件做法本项目的对应实现
地图匹配：GNSS 点永不直接上车标，先吸附到道路（TomTom / 高德定位白皮书）上报坐标投影到轨迹折线取弧长；动画只沿折线推进，坐标只决定目标进度
隧道丢星 → 软件航位推算：信号丢失时车标沿已知道路继续推进（TomTom Map Matching 文档原话 "advancing the chevron along its previously known route"）path 冻结但坐标前进 → 线尾沿路网 BFS 延展到最新上报点，车不悬空、不抄斜线
信号恢复：小误差融合吸收，大误差重新定位（snap），绝不倒退重放停等仲裁：上报点在车头之后 → 原地停等真实车；大幅超前 → 限制在周期预算内的受控追帧
速度剖面：两次定位间匀速插值 + 加减速平滑vCyc = 位移 ÷ 真实采纳周期（丢帧自动拉长预算），加速度限幅 1.2/1.8 m/s²，弯前 0.5m 线性减速 + 顶点限速
车头朝向：道路切向 + 平滑旋转车头仲裁取真实 robotDir：与运动同向→正行；反向→倒行（车尾对前进方向，即「倒着往目的地走」）；侧向不可信→随线；10rad/s 缓动永不瞬跳
长时间丢星：车标降级、置灰或隐藏失联 3 个周期：灰显 + 呼吸闪烁 + 「失联」徽标，位置冻结在最后可信点
与导航软件的一个本质差异
导航 App 有 1Hz 级 GPS + 惯导，可以放心做零滞后的航位推算；本系统只有 5s 一帧的历史轨迹（没有未来规划路线），所以采用「快速收敛到最新证据 + 沿路网延展」的折中：动画始终落后真实车 0～1 个周期，但永不超过证据点、永不倒退——这是「不漂移、不回头」约束下的最优解。

03缺陷清单与修复

编号等级现象根因与修复
A1严重·回头路车与目标在同一条边上时，动画先倒回节点、前进冲过目标、再退回——两段假回头路roadRoute 把两端各自吸附到最近节点，同边即生成「进又出」折线。重构为 graphRoute：BFS 后做反折消除（相邻段点积<0 的节点删除直连）；起点落在 A→第一跳边中段时砍掉吸附节点直接汇入
A2严重·回头路车越过冻结的轨迹尾后，折线先向后 1m 再向前——动画可见倒退节点过滤条件 cum≥t1−0.02 在车头投影被钳到轨迹尾之外时，仍会把身后的尾节点捡回线里。新增 npExhausted 判定：车头越过轨迹尾后不再拾取历史节点，改由 DR 延展接管
A3严重·漂移任务收尾（path 清空）或轨迹耗尽时，动画走「无任务缓动」直线扑向最新上报点，斜穿货架区全线锚定路网：线头永远锚在车头、中间走历史段、尾部按需 graphRoute 延展到上报点、无 path 时用「两点贴路追踪线」；直线缓动只允许收尾 ≤0.5m 微调与重定位瞬移
A4中·断帧path 冻结（现场 RSSI 故障实测存在）但坐标正常上报时，动画停在旧线尾，等 path 恢复后一整段距离一次冲刺新增航位推算兜底：上报点越过轨迹尾 0.25m 以上即沿路网延展线尾到上报点，逐帧跟随真实位置；上报点离路（地图版本差）时按原语义收到最近节点
A5中·丢包丢包重发的旧帧与真实新帧一视同仁重建线；步速超过物理极限的异常采样会把车拽跑新增帧可信度分层（ingest）：坐标零变化→停等（2 周期后清残线）；步速>2.5m/s→弃坐标保线；正常→采纳并按真实采纳间隔计追帧预算
A6中·健壮posX/posY 缺失 → NaN 毒化缓动目标，车从画布消失；path 中一个坏 JSON 点会让整帧全部车辆处理中断坏帧整条丢弃（isFinite 守卫）；path 逐点 try/catch + 过滤；抽出 ingest() 单帧处置函数（同时让帧逻辑可单测）
A7中·真实感车头永远等于运动切向：真实倒车时显示成「车头朝前正常行驶」；转弯动画被 5s 推送打断时车头瞬跳新增 resolveHead 车头仲裁：同向→真实 robotDir；反向→倒行模式（车头背向前进方向、位置仍沿 s 前进＝「倒着往目的地走」，画布加「倒行」徽标）；侧向不可信→随线；车头 10rad/s 缓动，任何切换不瞬跳
A8低·显示「暂停/排除」徽标 y 坐标写成 -w*0.9，画到画布顶端外，永远看不见修正为 py-w*0.9（车头侧）
A9低·语义顶栏「离线」计数实际统计的是「在其他地图」的车；真失联（3 周期无数据）不计数、不标识；服务器 online 字段（实测 A6 存在）完全未使用计数改为真失联；失联车灰显呼吸 + 编号徽标「·失联」+ 列表「失联」标签；接入服务器 online 字段（缺省在线）
A10低·体验拖动地图松手落在车上会误改选中；地图加载失败静默；首轮轮询因 loadMap 竞态白等 5s；图例把追踪段标成「规划路线」误导拖动位移>5px 不算点击；loadMap 失败显示错误；loadMap().then(poll) 修竞态；图例改「行进轨迹（至最新上报）」并补「失联」图例

04新动画引擎的工作方式

① 帧可信度分层
ingest()，每 5s 每车
坐标与上帧相同 → 停等（真停或 RSSI 重发，绝不外推）；步速>2.5m/s → 弃坐标保线；正常 → 采纳，追帧预算按真实采纳间隔计算。被过滤的帧不重建线：poly/s/sEnd 原样继承，车稳稳停在线上
② 贴路构图
setRoute() + graphRoute()
线头锚车头当前位置 → 拼接历史轨迹中车头之后的节点 → 上报点越过轨迹尾时沿路网 BFS 延展到上报点（隧道模式）→ 反折消除 + 去重。产出的折线每一段都是道路、都朝目标方向
③ 弧长推进
frame() 每帧
s 以 vCyc 匀速推进、加速度限幅、s 封顶 sEnd（= 最新上报点的投影）——结构上不可能越过证据点、不可能往回走；弯前 0.5m 减速、角点冻结旋转（贴合 AGV 在旋转码原地转向的真实行为）
④ 车头仲裁
resolveHead()
真实 robotDir 与运动切向对照：同向→正行；反向→倒行（车尾对前进方向＝倒着走向目的地，加「倒行」徽标）；侧向不可信→随线。车头 10rad/s 缓动
⑤ 失联降级
3 个周期无数据或服务器 online=false：灰显 + 呼吸闪烁 + 失联徽标，位置冻结在最后可信点；恢复后受控追帧
